## Matrix ownership and the v1.4 boundary

Matrix shipped its runtime, adapters, clients and `mxctl` from its own repository starting with 1.2.0. That tree also owns the structured-evidence wire schemas and golden examples. Main still compiles their version into the kernel, calls the peer from Server, exposes reports to clients and ships Matrix operator commands in `mmctl`. Deleting paths containing the word “matrix” would break the build and miss the provider in a mixed-purpose source file. [Matrix project](https://github.com/iokaio/munarium-matrix) · [Wire contract](../../contract/README.md) · [Server evidence provider](../../src/munarium-server/src/evidence_providers.rs)

Matrix owns the command and query definitions, schemas, examples, manuals and producer tests. Remove superseded main-tree copies once a comparison against v1.4 shows that scripts, saved runbooks and clients still work against their installed peer.

### Independent Lens replicas

The proposed Lens topology uses independently sized embedding and reranking pools. A small installation may co-locate both stages on one GPU. Record build and interactive query performance separately when they compete for embedding capacity. The scale-out design owns the operator resize decision and its acceptance tests. [SC1](scale-out.md#sc1)

Route by the requested stage and exact served identity. After importing pinned assets, each replica verifies the manifest and runs a known embedding or rerank probe on its loaded runtime. Admit it only to the pool for that identity. A listening socket is insufficient for readiness. An incompatible or warming replica stays out of rotation. Healthy saturation returns bounded overload after a capped queue wait. Size concurrency, queue depth and batch token limits from measured memory headroom and end-to-end latency within Server's deadline. Scaling up adds execution slots while Server continues to enforce the collection owner's single budget across all callers and replicas under I2.

The scaling runbook should show per-stage ready replicas, in-flight work, queue age, refusals, timeouts, batch sizes, GPU memory and latency without request content or tenant labels. On scale-in, remove the replica from routing, finish admitted requests within their deadlines and account for any discarded work. Disable automatic load-balancer replays of submitted inference calls. Server must account for any permitted new attempt. For a model change, bring up a separately named pool, probe it and qualify it before enrolling it. Keep the prior pool available for pinned indexes and rollback. A change in embedding identity requires a compatible index built for it. [Server rollout and rollback procedure](../ops/deployment-runbook.md)

### SC2

Admit work to a shared Lens pool only with explicit, current authorization covering each participating tenant and compatible processing, location, retention and isolation requirements. Resolve the authenticated tenant, permitted collection, model binding and placement policy before sending any content, including build inputs, queries, retries and shadow traffic. Keep credentials, results and budget reservations scoped to the tenant. Any enabled cache of inputs, vectors or results must isolate entries and lookups by tenant, authorized binding and model identity, and honor that tenant's retention policy. Disable that cache when isolation or expiry cannot be enforced.

A tenant requiring isolation uses its approved dedicated pool. If that pool has no ready worker, apply the collection's configured stage policy, including any authorized fallback. Each fallback remains subject to placement checks. [Stage policy (I1)](airk-analysis.md#i1) · [Inference accounting (I2)](airk-analysis.md#i2)

**Freeze procedure.** In each named checkout, resolve the reviewed release or candidate ref with `git rev-parse --verify <ref>^{commit}`. Enumerate that exact commit with `git ls-tree -r -l -z <commit>`. Parse the NUL-terminated records as mode, type, object ID, byte size and path. Record regular blobs by path, including tests, examples, build scripts and tracked generated interfaces. Classify each path as documentation, source or excluded with a reason. Review unrecognized extensions, large-file pointers and gitlinks explicitly. Treat symlinks as link entries and never follow them outside the pinned tree. Build the authorized input from reviewed Git objects to avoid untracked files and local modifications. Pin the completed Lens and reconciled Matrix candidates at the actual freeze.

From the repository root, run `py scripts/lens_workspace.py freeze <ignored-manifest> --workspace <workspace> --pin <root>=<full-commit>` with one `--pin` per authorized root. Then run `py scripts/lens_workspace.py verify <ignored-manifest> --workspace <workspace>` to re-enumerate the trees and compare every entry. The tool records missing roots and unresolved classifications. It excludes symlinks and I3 evaluation material and reads no files from the working tree. Keep an explicitly approved restricted manifest within its authorized boundary and use `--restricted-authority <opaque-record>` only for that run. This produces the Git input inventory for LENS-D2-T1. The ingestion reconciliation and per-file outcome records follow the inventory.
